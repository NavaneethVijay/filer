# Filer — agent context

Offline Android file manager + search by meaning (EmbeddingGemma 2, on-device). Sideloaded APK, not on Play. This file is the single source of agent context: architecture, conventions, backlog and status. Keep it updated when behaviour changes. User-facing overview and install steps: [`README.md`](README.md) (keep it in sync with features).

## Build & run

- Kotlin + Jetpack Compose (Material 3), single module `:app`, package `com.navaneeth.filer`, minSdk 31, targetSdk 35.
- **The user's phone runs the `release` build** (`com.navaneeth.filer`): R8, not debuggable, signed with the Filer release key (`CN=Filer`, alias `filer`, generated 2026-10-28). `./gradlew :app:assembleRelease` → `app/build/outputs/apk/release/app-arm64-v8a-release.apk`, install with `adb install -r` (an update keeps data). The key is `~/.android/filer-release.jks`, its path/passwords in `~/.gradle/gradle.properties` (`FILER_RELEASE_*`, read by `app/build.gradle.kts`; never commit them). Every update must use this key, or Android refuses it without an uninstall (which deletes the 485 MB model and index). Sideloaded only, no Play Store. The `benchmark` build (`.benchmark` suffix, debug key) is for local performance work only; it would install as a separate app. Debug builds are very janky (3–30× worse frame times) — don't judge UX on them.
  - One APK per ABI (`splits.abi`): arm64-v8a for the user's phone (~96 MB; also armeabi-v7a, x86_64). Release/benchmark run **R8** (`isMinifyEnabled` + `isShrinkResources`, rules in `app/proguard-rules.pro`: native/reflection libs kept whole). A crash only in release-type builds → likely a missing keep rule. The R8 "error occurred when parsing kotlin metadata" warnings are the known Kotlin version mismatch, harmless.
  - 2026-10-27: the user uninstalled the old `.benchmark` app (its data went with it) and installed the release build fresh to test end to end. Don't take screenshots or read logs during their testing unless asked.
  - `./gradlew :app:installBenchmark` / `:app:installDebug`
- Build output shows many `e: ... Module was compiled with an incompatible version of Kotlin` lines and sometimes `Daemon compilation failed: null`. These are from dependencies (Kotlin 2.0 project vs 2.2–2.4 libs); the build falls back and succeeds. Check for `e: file:///…/file-search/…` lines or `BUILD FAILED` to find real errors.
- Device: a Pixel 8 Pro is usually connected over adb (`adb devices`). **The user uses this phone** — ask before installing, clearing data, uninstalling, or granting permissions. Uninstall/clear data deletes the 485 MB model. Don't press "Turn on" for smart search unprompted (485 MB download).
- Screenshots: `adb exec-out screencap -p > $SCRATCH/x.png; sips -Z 700 …`. Device is 1008×2244; tap coordinates = screenshot coords × (2244/screenshot height). Wait ≥2 s after navigation before tapping (taps during transitions hit the incoming screen).
- Frame jank: `adb shell dumpsys gfxinfo <pkg> reset` → interact → `dumpsys gfxinfo <pkg>` (look at Janky frames / 99th percentile).

## Code map (`app/src/main/java/com/navaneeth/filer/`)

- `data/storage/Storage.kt` — all-files access, volumes, MIME, **`IndexRules`** (what is embedded / skipped / secret).
- `data/media/MediaLibrary.kt` — MediaStore queries: recent, categories, counts, whole-device name search, change observer.
- `data/browser/FolderBrowser.kt` — `java.io.File` listing for the folder UI.
- `data/files/` — `FileManager` (singleton: rename, new folder, copy/move, Recycle bin, Locked folder, favourites; emits `changes`) + `FileManagerDatabase` (separate `files.db`, non-destructive).
- `data/search/QueryParser.kt` — natural query → filters (type/date/date field/folder/size/place) + leftover words; unit-tested (`./gradlew :app:testDebugUnitTest`).
- `data/ai/` — AI plugins (optional downloads, per file, work without smart search): `AiPlugin`/`OcrScript` (model files, sizes) + `DeviceCapability`, `AiPluginManager` (downloads), `AiFeatures` (runs plugins on view/tap; `EmbedderEngine.exclusive` per model run), `OcrEngine`/`OcrMath` (PP-OCRv6, ONNX), `WhisperEngine`/`WhisperMath`/`AudioStream` (Whisper tiny, ONNX), `TagSuggester` + `TagLabels` (suggested tags = labels embedded as search queries, scored against the file's vectors like search), `PluginData` + `PluginStore` (files.db tables, follow file moves), `PluginIndex` (plugin passages' reserved page numbers), `AiText` (tag rules, rule-based names, dates/titles in text; unit-tested).
- `data/places/` — `Gazetteer` (offline GeoNames from `assets/places.tsv`; rebuild with `tools/build_places.py`), `PhotoPlaces` (EXIF GPS → place, `photo_places` table), `PlaceScanWorker`.
- `data/analysis/` — Storage tab: `StorageAnalyzer` (singleton, scans + keeps results), `ContentInsights` (smart-search insights: `ContentKind` words, `ContentAnalyzer` sorts indexed files into kinds from stored vectors — similar shots, forwards, sensitive files, space by kind; never runs the model, label vectors come from the tag cache and are made by `IndexRepository.prepareContentLabels` at the end of a pass), `StorageScanner` (one walk per volume), `PathRules` (where a file lives → source/clutter), `DuplicateFinder`, `StorageInsights` (pure: forecast, growth, highlights; unit-tested), `StorageReport` models.
- `data/crawler/LocalFolderCrawler.kt` — walks smart-search folders (and every volume for "Whole phone") for indexing.
- `data/repository/IndexRepository.kt` — discovery (`discoverAll` across all sources, one row per path), `runFullIndex` (serialised by a mutex; `reindexAll` resets inside the pass), per-file transactional embed, prune/reset/clear, storage breakdown. Singleton via `getInstance`.
- `data/repository/SearchRepository.kt` — hybrid scoring (z-gate + FTS coverage + kind hints).
- `data/vector/VectorIndex.kt` — in-memory float16 matrix from the `embeddings` table; per-kind centring; `invalidate()` after writes.
- `data/inference/EmbedderEngine.kt` — MediaPipe `UniversalEmbedder` (GPU text + CPU vision hybrid; CPU fallback), prompts (`formatDocument`/`formatQuery`), fallback vectors, `EngineTag` (engine stored per vector). Global `Mutex` for one phone inference at a time; `embedDocuments`/`embedPhoto` send indexing work to the Mac when asked and fall back to the phone.
- `data/inference/RemoteEmbedder.kt` — Developer mode: client for the Mac embedder (`http://127.0.0.1:9379` via `adb reverse`; `/health` + `/embed`, base64 float32 LE vectors), accepted only for the same model file; 10 s health cache, 30 s back-off after a failure. Queries never go here.
- `data/worker/IndexingWorker.kt` (one-off + 6-hourly periodic; battery/charging rules; `enqueueViaMac`), `ThermalGovernor.kt` (`awaitCapacity(routineRests = false)` when the Mac runs the model), `EngineCompareWorker.kt` (Developer › Compare engines).
- `data/model/ModelDownloadManager.kt` — singleton; `launchDownload()` only from explicit UI actions.
- `data/db/` — Room `filer.db` (**destructive migrations**; bump `version` on schema change). Entities: sources (smart folders, `LOCAL_FOLDER` path), files, chunks (`embedded` flag), embeddings (float16 BLOB, `engine` tag, FK cascade; v6), `chunks_fts`/`files_fts` (FTS4 porter, external content), index_runs/activity_logs (capped at 30, debug only — no UI).
- `ui/navigation/` — `NavRoutes` (type-safe), `FilerNavGraph` (bottom bar overlay, search overlay, access gate, transitions), `Motion` (M3 easing/specs).
- `ui/viewmodel/` — `LibraryViewModel` (activity-scoped: MediaStore + smart folders + model), `FileOpsViewModel` (activity-scoped, provided as `LocalFileOps`: dialogs, Move/Copy clipboard, messages), `FolderViewModel` (per back-stack entry), `SearchViewModel`, `IndexViewModel`, `SettingsViewModel`, `StorageViewModel` (activity-scoped).
- `ui/components/` — shared rows/sheets/thumbnails (`FileItems`, `FileVisuals`, `FileActionsSheet`, `FileSearchBar` = `SearchPill` + `SearchOverlay`, `SettingsRows`, `ViewOptions` = top-bar sort + list/grid, `SmartSearch` banner/enabler, `IndexBits`, `FileOps` = `FileOpsHost` dialogs/snackbars + `TransferBar` + `Selection`/`SelectionTopBar` + `FileManageRows`, `StoredItems` for bin/locked lists).
- `ui/screens/storage/` — Storage tab screens (overview, insights, cleanup review, duplicates, space map); `StorageStyle` maps kinds/types/sources to labels, icons, accents, shapes. ## Conventions (follow these)

- Material 3 components; strings in `res/values/strings.xml` (plurals for counts); no hard-coded UI text.
- Every new screen: `Scaffold` + a **large bold title that shrinks into the bar as you scroll** — `BoldLargeTopBar` with `exitUntilCollapsedScrollBehavior` + `nestedScroll`, or on Storage screens `StorageTopBar` + `ScreenHeader` (title and subtitle as the first list item, small title fades into the bar once scrolled). In selection mode switch to a pinned small bar (`SelectionTopBar`). Lists draw behind the floating nav pill: add `LocalBottomBarSpace.current` to the list's bottom `contentPadding` and lift bottom-anchored bars by it (it is 0 when the bar is hidden); don't add top/bottom padding the bar overlay already handles.
- Visual style is a hybrid of M3 (structure, components, colour roles) and M3 Expressive touches, **tonal and low-colour** (2026-10-27): one muted hue family taken from the theme's `secondary` — `Accent.colors()` derives every container by mixing the strong colour into the surface (`CONTAINER_MIX`), so no bright pastel/"neon" fills; BLUE/TEAL/SKY are the same family now and kinds are told apart by **shape** (cookie, squircle, flower, pill), not hue; SLATE is neutral; GREEN = safe/free and AMBER = stale/warning only where they carry meaning; red only destructive. File-type tiles (`FileKind.colors()`) are tonal too: folders on the accent tint, files on a neutral tile with the icon in `secondary`. Storage chart colours (`SpaceType.color()`) are lightness steps of the scheme. Never use the theme's `primaryContainer`/`secondaryContainer`/`tertiaryContainer` for fills (saturated in Filer blue) — use `Accent.BLUE.colors().container`. No hex colours outside `ui/theme` and the two state accents, so Settings › **Use phone colours** (default on, wallpaper scheme; off = Filer blue) restyles everything. Page titles and each card's key value bold (`ExpressiveType.LargeTitle` / `Number`, same size across cards), other text regular/medium. Navigation cards (Browse categories, Favourites/Bin/Locked) are compact (~72dp): shaped icon chip + name, count small and grey — the action leads, not the number. A title with a size goes on two lines (title, then size/summary under it), never side by side; where a number and a label share a line, align them with `alignByBaseline()`. Bottom navigation is the floating pill (`FilerBottomBar`, tabs Browse · Storage · Insights): selected tab expands with its label; Search is a separate round button beside the pill (Google Photos style) that opens the search overlay, not a tab. Settings is not a tab: a gear in Browse's header opens it (a Browse child with a back arrow). Unknown-length waits use `ExpressiveLoader`, determinate ones `WavyProgressIndicator`.
- File lists follow one rule: tap opens, long-press selects (`rememberSelection` + `SelectionEffects` + `SelectionTopBar`), ⋮ opens `FileActionsSheet`; while selecting, the row toggles, `SelectionCheck` sits on the right and the preview still opens the file (`FileListItem(onPreview = …)`). Don't cover a preview with the check. File AI/index info lives on the details screen, reached from the sheet's Details row.
- Show a real preview (`FileThumbnail`: image, video frame + duration, PDF page, album art, APK icon) wherever a specific file is shown; never a plain type icon instead.
- Wrap roots in `Surface` (not `Box.background`) so text gets the right content colour in dark mode.
- Heavy list mapping off the main thread (`flowOn(Dispatchers.Default)` or IO in repositories); `distinctUntilChanged` before `stateIn`.
- Haptics via `rememberHaptics()` (tick for selections, toggle for switches, longPress, confirm/reject).
- Logs: warnings/errors only, **never file names or user content**.
- Model work must go through `IndexingWorker` (never from a ViewModel) and call `thermal.awaitCapacity()` before each model run. Exception: AI plugins run on demand through `AiFeatures` (app-scoped), taking `EmbedderEngine.exclusive` per run and refusing when SEVERE-hot; their background part is `PhotoTextWorker`.
- `files.db` is never rebuilt: schema changes need a migration whose SQL matches Room's exported schema (`app/schemas/`, checked by `FilesDbMigrationTest`).
- Build for Android phones in general, not the test Pixel: gate heavy features with `DeviceCapability`, fall back (GPU→CPU) instead of assuming hardware.
- Indexing changes that alter vectors → bump `PreferencesManager.CURRENT_INDEX_VERSION` (forces a rebuild).
- Commits only when the user asks.

## Indexing & search (how it works)

- **Sources:** smart folders (`LOCAL_FOLDER`, canonical path) and optional **Whole phone** (`DEVICE`, `device://all`: every volume, skipping `/Android`, hidden and cache dirs). One row per path, owned by the first covering source (folders before Whole phone); removing a source hands files to another source with vectors kept.
- **Discovery** (no model): `discoverAll` marks new/changed files `PENDING`, unreadable types `SKIPPED` (still name-searchable), prunes gone files; batched in transactions of 500. Runs on source add, app launch, each pass and the 6-hourly job. Order: documents before photos, newest first.
- **What is embedded** (`IndexRules`): images ≥ 20 KB, PDFs, user documents/notes/code (`.txt`, `.md`, `.docx`, `.odt`, `.csv`, `.tsv`, code files via `OfficeTextExtractor` and `DocumentText`). Never videos/audio (name search only), secrets (keys, certs, keystores, password DBs, `.env`, SSH keys), or app noise (logs, xml, configs, dumps, temp files). File types can be turned off in Settings (`IndexKind`).
- **Unreadable files:** `UnreadableFileException` `PROTECTED` (password PDF → `SKIPPED`) or `UNREADABLE` (→ `FAILED`, not retried until size/mtime changes). Failed files count as finished in progress.
- **Chunking:** 200-word passages, 10-word overlap, short tails merged; number-heavy passages are keyword-only (`embedded = false`).
- **Prompts** (index v3, `EMBEDDING_GEMMA_2_V2`): documents `task: search result | text: …` (≤ 2000 chars, no file name), queries `task: search query | text: …` (≤ 500 chars).
- **No duplicates:** passes serialised by a `Mutex`; a file's passages + vectors replaced in one transaction; unique index on `embeddings.chunkId`; each pass first removes orphans. `VACUUM` after rebuild/clear/source removal.
- **Search** (`SearchRepository` + `VectorIndex`): cosine vs all vectors, centred per kind (text/image), one shared spread (floor 0.02) → z; candidate if z ≥ `Z_GATE` 2.0 or ≥ 50% of query terms found; score = 1.0·max(z,0) + 2.0·coverage^1.5 + 1.0 kind hint; codes/IDs → meaning ×0.5, words ×2. Float16 matrix built on first search, freed when the UI is hidden. Then whole-device file-name matches (MediaStore).
- **Natural search** (`QueryParser`, rule-based, English): types, dates, which date (added/taken/edited), apps/folders, size, places → MediaStore filters (`MediaLibrary.filtered`), so they need no index; leftover words narrow by name + smart search.
- **Heat & battery:** `ThermalGovernor` (full speed / short rests / pause when hot); bulk passes wait for charging + idle; "Index now" runs expedited; batches of 15 files with yields. Foreground notification with Pause/Resume/Stop.
- **Privacy:** MediaPipe telemetry stripped (`libs/tasks-core-patched.aar`, datatransport excluded, its services removed in the manifest, old DB wiped on launch). The model downloads only on a button press (two unexplained 485 MB downloads happened once from stray automated taps).
- **Index follows Filer's own file ops** (`applyFileChanges` + `FileChange`): rename/move re-points rows, copy clones vectors, bin parks rows as `GONE`, Locked drops them. Moves by other apps are still delete + new.

## AI plugins (rules)

- Plugin results live in `files.db` (v3: `file_text`, `file_tags`, `rename_suggestions`, `file_ai_cache`), keyed by path + mtime, following renames/moves/bin/restore; forgotten on delete and Lock. Every plugin works without smart search (keyword search over `file_text_fts`, `#tag`).
- With smart search on, `syncPluginText` (end of each pass) adds plugin text as passages with reserved page numbers (`PluginIndex.PAGE_OCR`/`PAGE_TRANSCRIPT`) and embeds only those. A photo's image vector isn't recomputed; stale text (mtime changed) isn't used.
- **Never break the existing index for a plugin:** no `filer.db` schema change, no `CURRENT_INDEX_VERSION` bump, plugin models use their own files; new tables go in `files.db` with a migration.
- Suggested tags (`TagSuggester`): ~100 `TagLabels` + the user's tags embedded once as queries (cached in `files/tags/labels.bin`, keyed by `MODEL_VERSION`), scored against the file's vectors like search; z ≥ `TAG_Z` 2.5 and within 1.5 of the best, top 4; plus metadata tags (chat app, screenshot, photo city). Under 50 vectors in the index → metadata tags only.
- Renames always go through `FileManager.rename()` and never happen automatically. Removing a plugin deletes its model and what it produced; tags the user added stay.

## Backlog

1. **Accuracy tuning:** tune `Z_GATE`, weights, chunk size, `TAG_Z`/`TAG_MARGIN` against real queries (the Mac embedder helps).
2. **Moved files by other apps:** detect by inode/size/mtime and re-path instead of re-embedding.
3. **Office docs:** `.xlsx`/`.pptx` are name-only; `.doc`/`.pages`/`.epub` not read.
4. **Strong vs weaker matches:** fold results below 50% of the top score under "weaker matches".
5. **Model lifecycle:** free the embedder after idle (~1 GB); consider a smaller/quantized model.
6. **Kotlin upgrade:** project is Kotlin 2.0.21, libraries ship 2.2–2.4 metadata (noisy errors, daemon fallback). Upgrade Kotlin/KSP/Compose plugin.
7. **Mac indexing speed:** 2–3 engine instances on the Mac, pipeline extraction on the phone (~14.6 items/s on M5 today).
8. **Tests:** have `QueryParserTest`, `QueryParserPlacesTest`, `StorageAnalysisTest`, `ContentInsightsTest`, `AiTextTest`, `OcrMathTest`, `WhisperMathTest`, `RemoteEmbedderTest`, `FilesDbMigrationTest`; add chunker, `IndexRules`, scoring, DAO/FTS instrumentation.
9. **Natural search:** localized date words, "between X and Y", place for videos (MP4 location atom).
10. Audio/video understanding (later, as plugins). Multi-select in the search overlay and Browse carousel.
11. **More Storage insights — follow-ups:** tune `ContentInsights.SIMILAR_MIN_COS` (0.93) / window (3 min) and `ContentAnalyzer.SENSITIVE_Z` (3.0) on real photos; make "What's in your files" rows open their files; more ideas: trips by place, saved twice across apps, long screen recordings/voice notes, videos worth compressing, old document versions, expired tickets (OCR dates), misfiled files.

**Untested on device:** Storage tab on a full phone (scan/duplicate time, SD cards; results aren't persisted), Recycle bin on SD cards, cross-volume moves (no progress UI), Locked folder PIN path.
